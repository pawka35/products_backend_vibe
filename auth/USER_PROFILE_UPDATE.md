# Обновление профиля и пароля пользователя

## Описание
Пользователи могут самостоятельно изменять свои данные (username, email) и пароль. Это позволяет пользователям управлять своим профилем без участия администратора.

## Эндпоинты

### 1. Обновление профиля
```
PUT /auth/me
```

### 2. Изменение пароля
```
PUT /auth/me/password
```

## Требования
- Необходим JWT токен (любого пользователя)
- Пользователь может изменять только свои данные

---

## 1️⃣ Обновление профиля (PUT /auth/me)

### Схема запроса: UserProfileUpdate
```json
{
    "username": "string",    // Новое имя пользователя (необязательно)
    "email": "string"        // Новый email (необязательно)
}
```

**Важно:** 
- Оба поля необязательны
- Можно обновить только username, только email, или оба сразу
- Хотя бы одно поле должно быть указано

### Примеры использования

#### Изменение только username
```bash
curl -X PUT "http://localhost:8000/auth/me" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "username": "new_username"
  }'
```

#### Изменение только email
```bash
curl -X PUT "http://localhost:8000/auth/me" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "email": "newemail@example.com"
  }'
```

#### Изменение username и email одновременно
```bash
curl -X PUT "http://localhost:8000/auth/me" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "username": "new_username",
    "email": "newemail@example.com"
  }'
```

#### Python пример
```python
import requests

BASE_URL = "http://localhost:8000"

# Получаем токен
response = requests.post(f"{BASE_URL}/auth/token", 
    data={"username": "john_doe", "password": "SecurePass123!"})
token = response.json()["access_token"]

# Обновляем профиль
headers = {"Authorization": f"Bearer {token}"}
update_data = {
    "username": "john_updated",
    "email": "john.updated@example.com"
}

response = requests.put(f"{BASE_URL}/auth/me", 
    json=update_data, headers=headers)

if response.status_code == 200:
    result = response.json()
    print("Профиль обновлен:", result["message"])
    print("Новый username:", result["user"]["username"])
    print("Новый email:", result["user"]["email"])
```

### Ответ сервера

#### Успешное обновление (200 OK)
```json
{
    "message": "Профиль успешно обновлен",
    "user": {
        "id": 1,
        "username": "new_username",
        "email": "newemail@example.com",
        "role": "customer",
        "is_active": true,
        "created_at": "2024-01-01T12:00:00Z",
        "updated_at": "2024-01-02T14:30:00Z"
    }
}
```

### Ошибки

#### 400 Bad Request - Не указано ни одно поле
```json
{
    "detail": "Необходимо указать хотя бы одно поле для обновления"
}
```

#### 400 Bad Request - Username уже занят
```json
{
    "detail": "Пользователь с таким именем уже существует"
}
```

#### 400 Bad Request - Email уже занят
```json
{
    "detail": "Пользователь с таким email уже существует"
}
```

#### 401 Unauthorized - Нет токена
```json
{
    "detail": "Not authenticated"
}
```

## 2️⃣ Изменение пароля (PUT /auth/me/password)

### Схема запроса: PasswordChange
```json
{
    "current_password": "string",    // Текущий пароль (обязательно)
    "new_password": "string"         // Новый пароль (обязательно, min 8 символов)
}
```

### Примеры использования

#### cURL пример
```bash
curl -X PUT "http://localhost:8000/auth/me/password" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "current_password": "OldPass123!",
    "new_password": "NewSecurePass456!"
  }'
```

#### Python пример
```python
import requests

BASE_URL = "http://localhost:8000"

# Получаем токен
response = requests.post(f"{BASE_URL}/auth/token", 
    data={"username": "john_doe", "password": "OldPass123!"})
token = response.json()["access_token"]

# Меняем пароль
headers = {"Authorization": f"Bearer {token}"}
password_data = {
    "current_password": "OldPass123!",
    "new_password": "NewSecurePass456!"
}

response = requests.put(f"{BASE_URL}/auth/me/password", 
    json=password_data, headers=headers)

if response.status_code == 200:
    print("Пароль успешно изменен!")
    
    # Проверяем вход с новым паролем
    response = requests.post(f"{BASE_URL}/auth/token",
        data={"username": "john_doe", "password": "NewSecurePass456!"})
    
    if response.status_code == 200:
        print("Вход с новым паролем успешен!")
```

### Ответ сервера

#### Успешное изменение (200 OK)
```json
{
    "message": "Пароль успешно изменен",
    "user": {
        "id": 1,
        "username": "john_doe",
        "email": "john@example.com",
        "role": "customer",
        "is_active": true,
        "created_at": "2024-01-01T12:00:00Z",
        "updated_at": "2024-01-02T15:00:00Z"
    }
}
```

### Ошибки

#### 400 Bad Request - Неверный текущий пароль
```json
{
    "detail": "Неверный текущий пароль"
}
```

#### 422 Unprocessable Entity - Слабый пароль
```json
{
    "detail": [
        {
            "loc": ["body", "new_password"],
            "msg": "Пароль должен содержать минимум 8 символов, заглавные и строчные буквы, цифры и специальные символы",
            "type": "value_error"
        }
    ]
}
```

#### 401 Unauthorized - Нет токена
```json
{
    "detail": "Not authenticated"
}
```

## 📋 Требования к данным

### Username
- ✅ Необязательное поле
- ✅ От 3 до 50 символов
- ✅ Должен быть уникальным в системе
- ✅ Рекомендуется: буквы, цифры, подчеркивание

### Email
- ✅ Необязательное поле
- ✅ Должен быть валидным email адресом
- ✅ Должен быть уникальным в системе
- ✅ Проверяется через EmailStr (Pydantic)

### Password (новый пароль)
- ✅ Обязательное поле
- ✅ Минимум 8 символов
- ✅ Максимум 128 символов
- ✅ Должен содержать:
  - Как минимум одну заглавную букву (A-Z)
  - Как минимум одну строчную букву (a-z)
  - Как минимум одну цифру (0-9)
  - Как минимум один специальный символ (!@#$%^&*()_+-=[]{}|;:,.<>?)

### Current Password (текущий пароль)
- ✅ Обязательное поле
- ✅ Должен совпадать с текущим паролем пользователя
- ✅ Используется для подтверждения личности

## 🔒 Безопасность

### Проверки при обновлении профиля
1. ✅ **Авторизация** - наличие валидного JWT токена
2. ✅ **Уникальность username** - проверка в базе данных
3. ✅ **Уникальность email** - проверка в базе данных
4. ✅ **Валидация данных** - через Pydantic схемы
5. ✅ **Изоляция пользователей** - пользователь может изменять только свои данные

### Проверки при изменении пароля
1. ✅ **Авторизация** - наличие валидного JWT токена
2. ✅ **Подтверждение личности** - проверка текущего пароля
3. ✅ **Сложность пароля** - соответствие политике безопасности
4. ✅ **Хеширование** - новый пароль хешируется перед сохранением
5. ✅ **Валидация данных** - через Pydantic схемы

### Логирование
Все операции обновления профиля и изменения пароля логируются:
- Кто обновил (user_id)
- Когда обновил (timestamp)
- Что изменил (поля)
- IP адрес запроса

### Важные моменты безопасности

#### ✅ Токен остается валидным
После изменения пароля текущий JWT токен остается валидным до истечения срока его действия. Это удобно для пользователя, но важно помнить:
- Если пользователь подозревает компрометацию, нужно выйти из всех сессий
- Рекомендуется реализовать функцию "выйти из всех устройств"

#### ✅ Старый пароль сразу перестает работать
После изменения пароля старый пароль больше нельзя использовать для входа.

#### ✅ Username изменяется, но user_id остается
При изменении username идентификатор пользователя (id) остается прежним, что важно для связей в базе данных.

## 📊 Диаграмма потока

### Обновление профиля
```
Пользователь → PUT /auth/me → Проверка токена → Проверка уникальности 
→ Обновление в БД → Возврат обновленного профиля
```

### Изменение пароля
```
Пользователь → PUT /auth/me/password → Проверка токена 
→ Проверка текущего пароля → Валидация нового пароля 
→ Хеширование → Сохранение в БД → Подтверждение
```

## ❓ FAQ

### Q: Нужно ли указывать оба поля (username и email) при обновлении профиля?
**A:** Нет, можно указать только одно поле. Но хотя бы одно поле должно быть указано.

### Q: Что происходит с токеном после изменения пароля?
**A:** Текущий токен остается валидным до истечения срока его действия. Новые входы требуют новый пароль.

### Q: Можно ли изменить роль через эти эндпоинты?
**A:** Нет, роль пользователя могут изменять только администраторы через `/admin/users/{id}/role`.

### Q: Что если я забыл текущий пароль?
**A:** Функционал восстановления пароля должен быть реализован отдельно. Эти эндпоинты требуют знания текущего пароля.

### Q: Могу ли я изменить username на уже занятый?
**A:** Нет, система вернет ошибку 400 с сообщением "Пользователь с таким именем уже существует".

### Q: Изменяется ли поле updated_at при обновлении?
**A:** Да, поле `updated_at` автоматически обновляется при любом изменении профиля или пароля.

### Q: Можно ли изменить email на уже зарегистрированный?
**A:** Нет, каждый email должен быть уникальным. Система вернет ошибку 400.

## 🔄 Сравнение с административным обновлением

|----------|----------------------------------|---------------------------|
| Эндпоинт | `PUT /auth/me` | `PUT /admin/users/{id}` |
| Требуется токен | ✅ Да (свой) | ✅ Да (admin) |
| Может изменять | ✅ Только свои данные | ✅ Любого пользователя |
| Может изменить роль | ❌ Нет | ✅ Да |
| Требует текущий пароль | ✅ Да (для смены пароля) | ❌ Нет |
| Проверка уникальности | ✅ Да | ✅ Да |
