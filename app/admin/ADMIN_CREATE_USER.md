# Создание пользователя администратором

## Описание
Администраторы могут создавать новых пользователей с любой ролью, включая роль администратора. Это полезно для первоначальной настройки системы и управления пользователями.

## Эндпоинт
```
POST /admin/users
```

## Требования
- Необходим JWT токен администратора
- Роль пользователя, выполняющего запрос: `admin`

## Схема запроса

### AdminUserCreate
```json
{
    "username": "string",    // Имя пользователя (3-50 символов)
    "email": "string",       // Email пользователя (валидный email)
    "password": "string",    // Пароль (минимум 8 символов)
    "role": "string"         // Роль: "admin", "customer" или "executor"
}
```

## Примеры использования

### 1. Создание обычного пользователя (customer)
```bash
curl -X POST "http://localhost:8000/admin/users" \
  -H "Authorization: Bearer YOUR_ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "username": "john_doe",
    "email": "john@example.com",
    "password": "SecurePass123!",
    "role": "customer"
  }'
```

### 2. Создание исполнителя (executor)
```bash
curl -X POST "http://localhost:8000/admin/users" \
  -H "Authorization: Bearer YOUR_ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "username": "executor_jane",
    "email": "jane@example.com",
    "password": "SecurePass123!",
    "role": "executor"
  }'
```

### 3. Создание администратора (admin)
```bash
curl -X POST "http://localhost:8000/admin/users" \
  -H "Authorization: Bearer YOUR_ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "username": "admin_smith",
    "email": "smith@example.com",
    "password": "SecurePass123!",
    "role": "admin"
  }'
```

### 4. Python пример
```python
import requests

# URL сервера
BASE_URL = "http://localhost:8000"

# Получаем токен администратора
login_data = {
    "username": "admin",
    "password": "admin123"
}
response = requests.post(f"{BASE_URL}/auth/token", data=login_data)
admin_token = response.json()["access_token"]

# Создаем нового пользователя
headers = {"Authorization": f"Bearer {admin_token}"}
user_data = {
    "username": "new_user",
    "email": "newuser@example.com",
    "password": "SecurePass123!",
    "role": "customer"
}

response = requests.post(
    f"{BASE_URL}/admin/users",
    json=user_data,
    headers=headers
)

if response.status_code == 200:
    print("Пользователь создан:", response.json())
else:
    print("Ошибка:", response.text)
```

## Ответ сервера

### Успешное создание (200 OK)
```json
{
    "id": 10,
    "username": "john_doe",
    "email": "john@example.com",
    "role": "customer",
    "is_active": true,
    "created_at": "2024-01-01T12:00:00.000000+00:00",
    "updated_at": null
}
```

### Ошибки

#### 400 Bad Request - Пользователь с таким именем уже существует
```json
{
    "detail": "Пользователь с таким именем уже существует"
}
```

#### 400 Bad Request - Пользователь с таким email уже существует
```json
{
    "detail": "Пользователь с таким email уже существует"
}
```

#### 403 Forbidden - Недостаточно прав
```json
{
    "detail": "Требуются права администратора"
}
```

#### 422 Unprocessable Entity - Невалидные данные
```json
{
    "detail": [
        {
            "loc": ["body", "password"],
            "msg": "Пароль должен содержать минимум 8 символов",
            "type": "value_error"
        }
    ]
}
```

## Требования к данным

### Username
- ✅ Обязательное поле
- ✅ От 3 до 50 символов
- ✅ Должен быть уникальным
- ✅ Рекомендуется использовать буквы, цифры и подчеркивание

### Email
- ✅ Обязательное поле
- ✅ Должен быть валидным email адресом
- ✅ Должен быть уникальным

### Password
- ✅ Обязательное поле
- ✅ Минимум 8 символов
- ✅ Максимум 128 символов
- ✅ Должен содержать:
  - Как минимум одну заглавную букву
  - Как минимум одну строчную букву
  - Как минимум одну цифру
  - Как минимум один специальный символ

### Role
- ✅ Обязательное поле
- ✅ Допустимые значения:
  - `admin` - Администратор системы
  - `customer` - Заказчик
  - `executor` - Исполнитель заказов
- ✅ По умолчанию: `customer`

## Отличия от обычной регистрации

| Функция | Обычная регистрация | Создание администратором |
|---------|-------------------|------------------------|
| Создание роли admin | ❌ Запрещено | ✅ Разрешено |
| Требуется авторизация | ❌ Нет | ✅ Да (admin) |
| Эндпоинт | `/auth/register` | `/admin/users` |
| Роли по умолчанию | `customer` | `customer` |
| Валидация пароля | ✅ Да | ✅ Да |

## Безопасность

### Что проверяется
1. ✅ **Авторизация** - наличие валидного JWT токена
2. ✅ **Роль** - пользователь должен быть администратором
3. ✅ **Уникальность username** - проверка в базе данных
4. ✅ **Уникальность email** - проверка в базе данных
5. ✅ **Сложность пароля** - соответствие политике безопасности
6. ✅ **Валидация данных** - через Pydantic схемы

### Логирование
Все операции создания пользователей логируются:
- Кто создал (администратор)
- Когда создал (timestamp)
- Какого пользователя создал (username, role)
- IP адрес запроса

## FAQ

### Q: Может ли администратор создать другого администратора?
**A:** Да, администратор может создавать пользователей с любой ролью, включая `admin`.

### Q: Какие требования к паролю?
**A:** Минимум 8 символов, должен содержать заглавные и строчные буквы, цифры и специальные символы.

### Q: Можно ли создать пользователя с ролью admin через обычную регистрацию?
**A:** Нет, через `/auth/register` создание администраторов запрещено. Только через `/admin/users`.

### Q: Что происходит при попытке создать пользователя с существующим email?
**A:** Возвращается ошибка 400 с сообщением "Пользователь с таким email уже существует".

### Q: Может ли не-администратор использовать этот эндпоинт?
**A:** Нет, эндпоинт доступен только пользователям с ролью `admin`. При попытке доступа без прав администратора вернется ошибка 403.
